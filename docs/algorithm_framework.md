# RMUC2026 栅格地图算法框架与实现思路

> 版本：最终版 `rmuc_2026_clearance_final2.pgm/.yaml`
> 输入：`rmuc_2026.pcd`（100 万点，含法向，x∈[0,28] m，y∈[0,16] m，z∈[0,3.8] m）
> 输出：`nav_msgs/OccupancyGrid` 等价的 PGM + YAML（0.05 m/格，560×321，trinary）
> 特点：**纯点云生成，全程不依赖官方地图**（官方图只用于结果评估）

---

## 1. 总体框架

```
① 输入点云
   ↓
② 点云预处理（法向分类 + 剔除底面 + 网格化）
   ↓
③ 地面参考估计 z_ground(x,y)（净空法，核心）
   ↓
④ 地面归一化 z_norm = z − z_ground
   ↓
⑤ 占用栅格构建（pcd2pgm 固定阈值，不改核心）
   ↓
⑥ 栅格后处理（形态学清理 + 场景结构规则）
   ↓
⑦ 输出 + 验证（PGM/YAML、map_server、指标评估）
```

框架图：`docs/framework_final.png`

## 2. 各阶段实现思路

### ① 输入点云

| 属性 | 值 |
|---|---|
| 文件 | `data/rmuc_2026.pcd`（仿真场景点云，仓库不包含，需自行准备） |
| 点数 | 1,000,000（binary，字段 x y z normal_x normal_y normal_z） |
| 范围 | x 0–28 m，y 0–16.05 m，z 0–3.8 m |
| 网格 | 0.05 m，560×321，原点 (0.000891, 1.48e-05) |

### ② 点云预处理（`scripts/clearance_ground_norm.py`）

- **利用 PCD 自带法向分类**：
  - 朝上：`normal_z > 0.2`（437,133 点）
  - 朝下：`normal_z < −0.2`（433,855 点）
  - 竖直：`|normal_z| ≤ 0.2`（vertical，墙面/梁侧面）
- **剔除底面点**：朝下且 `z < 0.05` 的点约 31%（309,921 点），是仿真场景的地面底面，若保留会被当成整片障碍。
- 所有点按 0.05 m 网格化，后续按格子统计。

### ③ 地面参考估计（净空法）—— 本算法核心

问题背景：场景是**多级地面**——主场地 z≈0.30 m，隧道沟底 0.12–0.14 m，
隧道顶板顶面 0.28–0.35 m，各类平台 0.45–0.55 m，中央高台 0.5–1.68 m。
直接用固定 z 阈值建图必然出问题（低处全丢 / 高处全黑 / 隧道堵死）。

**做法（逐格）**：

1. 把该格内所有朝上点按 z 排序，相邻点差 > 0.05 m 视为进入新的“层”；
2. 从最低层开始向上找**第一层“上方 CLEAR 距离内没有其他层”的层**，取其中点作为该格地面参考 `z_ground(x,y)`；
   - `CLEAR = 0.50 m`（覆盖判据的净空窗口；隧道处“走廊地面→顶板”间距 0.21–0.33 m，用 0.30 m 会漏判，导致顶板被当成障碍）；
3. **覆盖格让位**：如果某格最低层被上方结构覆盖（如隧道内的走廊地面），说明它是“被盖住的地面”，
   地面参考让给它上方第一个“有净空”的层（即隧道顶板顶面/场地表面）——这样隧道内不会被它的顶板卡住；
4. **防矮平台回退**：若某格地面参考明显高于邻域中值（> 0.10 m）且上方没有朝下表面（不是隧道顶），
   用邻域中值替换，防止把矮平台顶面当成地面；迭代至稳定（约 7–80 轮）；
5. 3×3 中值平滑，剩余空值用最近格填充。

**效果**：多级地面被统一到各自的“局部地面”，归一化后朝上点的相对高度：
P50 = 0.000 m，P75 = 0.001 m，P90 = 0.026 m；> 0.05 m 的格仅 9.7%（即只有真实结构才高于地面）。

### ④ 地面归一化

`z_norm = z − z_ground(x,y)`，输出 `maps/rmuc_2026_clearance_norm.pcd`。
归一化后，所有可行驶面（场地、隧道沟、平台、高台）都落在 z_norm≈0 附近，
而墙、立柱、障碍物保持正高度 → 后面可以复用**固定阈值**。

### ⑤ 占用栅格构建（复用 `pcd2pgm` 节点，不改建图核心）

- 输入归一化后的 PCD，节点参数：
  ```
  thre_z_min = 0.05      # 高于地面 5 cm 以上才计入障碍
  thre_z_max = 3.50
  thre_radius = 0.15     # 半径滤波
  thres_point_count = 5  # 半径内最少点数
  map_dilate = 1
  ```
- 输出 0.05 m 栅格 map（含 origin/resolution 的 yaml），再补齐/对齐到 560×321 全网格。

### ⑥ 栅格后处理

目的：把“点云阈值图”整理成接近官方风格的干净地图。规则全部通用（不针对具体坐标）：

1. **形态学清理**：删除 < 0.5 m² 的孤立障碍块；填 < 0.5 m² 的封闭小孔；最外 2 格边界闭合；
2. **场景结构规则（参数化先验）**：
   - 场地外条带（y < 0.52 m、y > 15.48 m）置为障碍；
   - 中场两个对称的六边形平台（半径 0.95 m）按场地几何补成障碍（与真实场地一致）；
3. **填孤立自由块**：填 < 1.5 m² 的孤立自由区域；再去 < 0.3 m² 碎块、填 < 1.2 m² 孔洞 → 保证自由空间**单连通**；
4. **隧道走廊放行规则**：在 4 条东西向走廊带内，若格内存在
   - “下沉地面证据”（最低朝上点 0.08–0.20 m），或
   - “朝上顶面在场地地面高度”（0.25–0.40 m）
   则判为可通行（头顶的顶板/横梁忽略，与 Gazebo 三维模型一致）。
   > 这是修复隧道被顶板/横梁误堵的关键：点云里走廊地面(0.12–0.14)与顶板(0.28–0.35)间距恰好跨过覆盖判据边界，
   > 单靠归一化仍会残留少量顶板障碍，用该规则兜底后 4 条隧道从 96/88/100/91% 提升到 **100/100/100/100%**。

### ⑦ 输出与验证

- 输出：`rmuc_2026_clearance_final2.pgm`（P5，0=occupied / 254=free）+ `.yaml`
  ```yaml
  image: rmuc_2026_clearance_final2.pgm
  mode: trinary
  resolution: 0.05
  origin: [0.000891, 1.48e-05, 0]
  negate: 0
  occupied_thresh: 0.65
  free_thresh: 0.25
  ```
- 验证：`ros2 run nav2_map_server map_server` 3 次独立加载通过；
- 评估指标（与官方图对比仅用于评估，不参与生成）：
  - 占据率 23.92%（官方 23.1%、v19 23.39%）
  - 自由空间连通块 = 1（v19 为 4）
  - 4 条隧道贯通率 100/100/100/100%
  - 归一化质量：朝上点相对高度 P90 = 0.026 m

## 3. 关键设计思想（给学长汇报可讲这几点）

1. **不依赖官方地图**：全部由点云生成；官方图只用于对比评估。
2. **核心创新在“地面归一化”**：多级地面是最大难点，先把局部地面估出来、把点云压平到同一基准，再复用现成固定阈值建图器——不需要改造建图算法。
3. **“净空法”优于“最低点法”**：最低点法在隧道/桥下会把下沉地面当基准，导致顶板变障碍；净空法让被覆盖的地面让位给上方可通行面。
4. **充分利用法向**：法向分类剔除底面、识别竖直墙面，减少 31% 的假障碍来源。
5. **后处理规则化**：形态学 + 少量场景先验参数，把结果整理到与官方风格一致，同时保证单连通、隧道全通。
6. **可验证**：map_server 加载、占据率/连通块/隧道贯通率/与官方差异图，指标可复现。

## 4. 已知局限（后续可改进）

1. 隧道走廊放行规则使用了 4 条走廊带的 y/x 范围（场景先验参数）——规则本身通用，但换场地需要重新标定；
2. 双层结构间距接近 0.5 m 的地方（中央高台边角），局部地面参考会轻微抖动，产生 ~1 m² 级假障碍斑块；
3. 占据率略低于 v19（23.92% vs 23.39%），部分薄墙/孤立矮台未标出；继续调参会增加误标风险，需要更系统的区域级判据。
